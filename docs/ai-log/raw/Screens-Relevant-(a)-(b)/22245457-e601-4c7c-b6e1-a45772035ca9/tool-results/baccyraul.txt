   215	### Chat 3, continued: the module and the system changes
   216	
   217	**The module**
   218	- **Conventions:** `today` is always passed in, unknown values are `null` and never 0, and dates stay strings. Every state is reproducible, and no screen does date maths.
   219	- **Default on day 30 (27 Aug),** because "30+ days" read literally includes day 30.
   220	- **Collection only when salary lands, never from other incoming money.** That's what the user agrees to. Collecting from any money drifts towards sweeping funds.
   221	- **Reminders:**
   222	  - before the due date: 25 Jul at 10:00,
   223	  - the not-collected notice: 6pm, when the attempt fails. 10:00 would go out before the attempt,
   224	  - late reminders every 7 days (a placeholder cadence),
   225	  - at most 2 in any 7 days in a row.
   226	- **The notice before default (20 Aug) is never paused,** even after a payroll delay is reported, because a material consequence must always be announced. Whether a delay should move the default date is a question, not a rule.
   227	- **`acceptTerms` is idempotent:** accepting the same terms twice returns the same advance, never a second one.
   228	- **The wallet shows the real balance,** with "Includes Rs 10,000 from your advance" on home after accepting only. On later days the balance is `null`, because spending isn't modelled. Elsewhere the advance card says "Received Rs 10,000 on 7 Jul · Rs 10,300 to repay on 28 Jul".
   229	- **The late state (S12) is viewed on 2 Aug** (5 days late).
   230	
   231	**The system**
   232	- **The frozen copy is allow-listed rather than skipped by the check,** so the exception stays narrow and visible.
   233	- **`formatAmount` in AmountText is the single money formatter,** so money in strings and in components always matches.
   234	- **Card tone borders:** attention-100 for attention, and neutral-200 for danger. Both are as faint against the page as the default edge (1.17 and 1.18:1). Full danger red would be an alarm line.
   235	- **Panel is a deprecated alias of Card,** so imports keep working and the duplicate is gone.
   236	- **The desktop scrollbar is hidden inside the frame,** because phones overlay theirs.
   237	
   238	**Calls the AI made during the build, flagged and not overruled**
   239	- **Button keeps its colours while loading,** because it's working, not unavailable. Its second line stays visible, so the height never changes. *Chat 4: S4's and S7's Accept have no second line now; S5 uses the loading state.*
   240	- **The AppBar glyph uses `text-display`, not the suggested `text-title`.** Measured, `text-title` only took it from 5px to 7px wide.
   241	- **A real zero still formats as "Rs 0".** Only missing data returns `null`, and a number passed as a string counts as missing.

     1	# NovaKit Lite
     2	
     3	A small slice of **NovaPay's coded design system** — the starter for the AI-First Product Designer case study. It gives you design tokens, a handful of components, and a running mobile-framed app to build on.
     4	
     5	> Read this and the components carefully — but treat the system as a **starting point, not gospel**. Real design systems are messier than their docs suggest: some things are missing, some are inconsistent, and some shouldn't be reused as-is. Part of your job is to notice that.

     9	```bash
    10	npm install
    11	npm run dev
    12	```
    13	
    14	Then open the local URL Vite prints. The app renders inside a ~390px mobile frame — keep your work mobile-first.

    17	npm run build   # production build (also a quick way to check nothing is broken)

    22	
    23	```
    24	src/
    25	  novakit/            # the design system — build from these
    26	    Button.jsx        # primary | secondary · md | lg · optional second line · loading
    27	    TextField.jsx     # default · focused · disabled
    28	    Card.jsx          # surface container · tones: default | attention | danger

    34	    AmountText.jsx    # formats PKR amounts (and formatAmount for strings)

    36	    index.js          # barrel export -> import { Button } from "./novakit"
    37	  advance/

    48	Tokens live in `tailwind.config.js` (e.g. `bg-brand`, `bg-brand-50`, `text-attention-600`, `text-neutral-700`, `rounded-md`, `shadow-card`, `text-title`). The palette is intentionally generous — a full brand (indigo) ramp, an amber `attention` ramp for states that need attention (soft background, dark text, never a solid fill), a `danger` colour only for a failed event, and a layered neutral scale — so you have room to make real aesthetic choices. Use it with restraint. Build new work from tokens and existing components; extend the system only where you genuinely need to, and keep design and code in sync.
